# v1.0.2：原系统页面与数据重新接合

## 基线和问题

本轮从 `codex/v1.0.1-data-access` 的 `127ee3d0c8bb572af87c4e1cf906fec564a74e63` 接续；它包含 v1.0.1 数据适配、生产配置和本机注册修补。核对时 main 仍停在 3c7bdc7，不从旧 main 覆盖已部署代码。不修改生产数据库、不改模型/指标/五档状态。

用户再次明确：原 ETF 决策面板是市场总览的一部分，不是登录页或独立主页。原代码的行业、概念、全市场目录必须接到新页面，不用新空壳替代原系统。

已复现的代码问题：
- `/classic/etf-board` 运行独立旧认证和导航；Vue 登录没有创建账户入口，文档反而要求去旧页面注册。
- 总览只提供简化表，完整指标表在 `/matrix`，原版又另开站点；同一个任务需要多次跳转。
- 总览无板块数据时整块被隐藏；行业与概念默认混排只显示涨幅前12项。
- 搜索仅查已同步 Instrument，完整目录依赖手工任务；目录和快照没有初始化状态联动。
- 生产只启用 worker，不等于目录/行业/概念任务会被创建；原 Provider 接口存在不等于持续采集已启用。

## 本轮必须通过的合同

R1：统一登录/邀请注册/关闭注册提示；管理员在账户管理创建成员。不能开放无邀请码的首个管理员注册，不能返回密码。
R2：登录后进入 `/`；主页常驻壳层。总览顺序为指数、A股宽度、行业/概念、原风格五档ETF决策快照。旧 matrix/classic 链接归一到总览内锚点；不再渲染第二套登录、页头或 iframe。
R3：决策快照复用现有 DecisionBoardService 与指标语义，保留量能、MA、MACD、KDJ、TD9、RSI、板块、1/3/5/10日预测和解释。所有标的只去 `/etf/{ts_code}`。
R4：行业与概念分别展示并可筛选、排序和展开；读取原 SectorSnapshot、MarketContextRegistry/Snapshot，不新建平行行情库。无数据/失败/陈旧明确显示，不静默隐藏。
R5：全市场场内ETF/LOF目录不以行业、enabled、自选/持仓过滤；目录与计算池分离。多源目录、源信息、范围、初始化/失败状态可见；搜索不触发网络或模型。
R6：低频 discovery 在已有 worker 内受配置、幂等、重试预算和队列控制；目录、板块任务独立于价格流水线。默认真实数据模式才可运行；Mock只用于测试。
R7：用户指定的上游工程逐个记录固定版本、许可证、具体文件和吸收点；提供隔离源码获取工具及快照。未复制的标明仅参考，未启动的不得宣称已部署。
R8：后端、类型检查、前端单测、标准Playwright及完整CI通过；先记录失败复现，再修复。测试和截图的Mock标签不可删。
