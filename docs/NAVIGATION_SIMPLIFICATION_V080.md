# v0.8.0 导航收敛说明

日期：2026-09-06

## 目标

本次只收敛页面切换、入口命名与 ETF 详情跳转，不修改策略、指标、预测、数据库模型、调度器或 14:30 决策口径。

此前的主要问题不是“页面不够多”，而是同一任务存在多套入口：`/legacy` 默认又出现一套决策看板、`/legacy#holdings` 没有真正的 hash 路由、总览和 14:30 又各自维护一套局部 ETF 详情弹层。结果是用户很难确认自己当前处于哪个工作区，以及点击标的后到底会去哪里。

## 收敛后的信息架构

### 四个常驻一级入口

| 名称 | 稳定入口 | 实际工作区 |
| --- | --- | --- |
| 🎯 决策 | `/` | 当日统一决策总览 |
| 🔥 板块 | `/boards` | 行业/概念板块宽度与 ETF 代理 |
| 💼 我的 | `/portfolio` | 307 到 `/legacy#holdings`，持仓与自选 |
| 🔬 研究 | `/research` | 307 到 `/legacy#signals`，信号/新闻/系统研究工作区 |

### 一个突出任务入口

`⏱️ 14:30` 保留 `/workbench/1430`，但语义是“每天尾盘执行的一次集中研究任务”，不再与四个常驻业务区混为同一层级。

### 一个全局 ETF 详情入口

所有列表型标的点击统一进入 `/etf/{ts_code}`。当前覆盖：

- 决策总览行；
- 14:30 候选行；
- 研究中心中的信号前排/分组/板块代理；
- 持仓表中的标的身份单元格；
- 板块页原有成员 ETF 链接（原本已使用 `/etf/{code}`）。

`/etf/{code}` 继续使用与 14:30 工作台同源的只读详情 API，不引入第二套计算口径。

## Legacy 兼容规则

- `/legacy#holdings` 现在会真正打开“持仓”页签；
- `/legacy#signals`、`#news`、`#system` 分别打开对应研究页签；
- `/legacy` 无 hash 时默认进入 `#signals`，不再默认展示重复的旧“决策看板”；
- 旧 dashboard DOM 暂时保留用于低风险兼容，但其页签入口由共享 App Shell 隐藏；主决策入口只有 `/`。

## 实现方式

新增 `backend/app/static/app_shell.js` 作为全站唯一导航契约。FastAPI 的用户可见 HTML 路由统一注入该同源脚本，因此各历史页面不再各自决定一级导航和跨页点击语义。

新增纯函数单测 `app_shell.test.js`，并把脚本语法检查与单测纳入 GitHub Actions。Python 路由测试同时锁住 `/portfolio`、`/research`、共享 App Shell 注入和 canonical ETF 详情选择器。

## 交接注意

- 无数据库迁移；
- 无 APP/策略版本升级要求；
- 上线只需要正常同步代码并重启/重建当前 Web 服务与静态资源；
- 后续若重构 legacy 页面，可以删除隐藏的 dashboard DOM 和旧局部详情弹层，但在删除前应继续保持本文件定义的稳定路由契约。
