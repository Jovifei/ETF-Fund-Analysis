# R4C 阶段实施计划（条件版）

日期：2026-09-27。依据本项目 9 月 22 日路线图、当前源码、项目知识库及远端 ChatGPT 的 M0–M5 规划整理。实施以 R4B 最终接收为前提；此页不是应用完成或生产发布收据。

## 目标与边界

下一完整阶段交付可解释、可回放、能说明何时才确认的缠论研究结构，沿用同一 ETF 详情页和价格基准。数值由确定性代码计算；LLM 只解释冻结证据；不产生第二套正式动作，不连接券商，不把箱体或旧重叠区改名为完整缠论，不提升真实数据或预测资格。

## 里程碑

| 阶段 | 交付与进入/退出条件 |
| --- | --- |
| M0 基线接收 | 完成 [R2–R4B 对账](audits/R2_R4B_RECONCILIATION_20260927.md)，固定最终 SHA/tree、收据、测试与跳过项；R4B 在途时只做只读盘点，不改其代码。 |
| M1 引擎与口径 | 核对现有 `chanlun` 分发包身份及 CZSC 的当前一手源码、许可证、依赖、Windows/Linux 和资源能力；选一种明确口径、固定版本/配置、记录分型/笔/线段/中枢能力矩阵。未知或不兼容版本拒绝计算。 |
| M2 因果结构 | 在独立模块/窄适配器实现输入、结构和状态合同；区分发生、算法确认与实际首次观察时间。用人工推导夹具、逐前缀回放、未来数据变更和历史修订测试证明无前瞻。缺失量额不伪造为零。 |
| M3 快照与任务 | 复用现有受审计队列，显式冻结输入、在 API 外有界计算、短事务发布可按版本寻址的结果；GET 只读，不调用 Provider、模型或引擎。失败不能覆盖有效快照。 |
| M4 页面证据 | 复用 Vue/KLineCharts 图表；分型、笔、线段、中枢与 R4B 箱体分层，按有效时间绘制，证据卡列口径、版本、来源截止、确认时间和缺失能力。切换标的、周期、价格基准时不混绘。 |
| M5 独立验收 | 绑定最终应用 SHA/tree 跑算法回放、迁移、完整后端/前端/浏览器回归与跨平台引擎实测；保存失败、重跑、资源、跳过和权限证据。代码、真实数据、PIT/OOS、生产状态分别给结论。 |

## 开源采用顺序

现有 `backend/app/services/kline_stabilization_service.py` 已有可选 `chanlun` 摘要路径，但计数不能证明几何或确认时点。优先审查其真实分发包，再对照 [CZSC](https://github.com/waditu/czsc) 的当前结构 API；Skill 只供开发参考，不能绕过 Provider Adapter 抓行情。AKQuant、Qlib 等保留为后续独立回测/滚动评估参考；KLineCharts 先维持项目固定版本。任何引入须固定上游提交、分发工件、许可证/NOTICE 和依赖树，不因框架更新而静默替换现有算法。

## 后续依赖

- N1：在冻结证据上做消息主体、否定、事件时间、转载去重和 ETF 暴露映射，人工标注集验收；不让模型改价格结构。
- R5：沿用现有本地 Bridge 的配对、队列和候选审核，先离线负例，真人登录与付费任务另作现场门禁。
- R6：按标的/日期/能力认证真实数据，再用可得时点做样本外、事件回测与 Shadow；日线回放不冒充历史 14:30。生产部署另走备份、镜像身份、CI、恢复与授权。

下一动作：完成 M0 后，将此条件计划按最终 R4B 代码与收据修订为可执行版本，再开始 M1。当前不修改 R4B 在途工作树或生产。
