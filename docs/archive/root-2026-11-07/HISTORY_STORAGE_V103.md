# v1.0.3 历史展示与存储合同

## 原因与本版修复

页面空白不是磁盘不足的证据。204a31c 的指数历史接口返回观察点，不是 OHLC；整池历史门禁和未计算的指标又让可展示数据消失。本版逐标的隔离共享计算，保留独立的历史价格展示。无成交量不补零，旧单位不盲目乘系数，缺失实时价格不伪造今日价格。缺少日线指标快照不应清除独立且有时间依据的盘中研究状态；旧单位/缺量数据仍不得靠盘中输入越过共享计算资格。

## 数据路径

ETF 沿用 DailyBar 和现有 Provider/MarketService。行情保存后不因网络失败删除；图表 GET 只读已有历史，用既有确定性公式计算价格类指标。后台 `recompute` 只重算已有数据；详情的“补齐历史并加入研究池”显式建立单标的任务并加入自选。全市场目录不等于全市场已下载历史；研究池继续有上限。

上证、沪深300、中证全指通过 Provider.fetch_index_bars 获取实际 OHLC，分别映射 sh000001、sh000300、sh000985。来源为 Tushare index_daily 或 AKShare 指数日线。禁止把 ETF 当指数或将观察点复制成四价。三只指数缓存暂用现有 WorkspacePreference 的 system:index-history 命名空间，每只最多1500条、请求最多1800自然日；版本、源日期、逐行来源、数据哈希保留，整批验证后合并，失败保留旧缓存。扩展大量指数前再迁到专用表。

实时卡片与日线缓存分开：只有取得对应日期的源数据才展示该日期；否则标最近收盘。缺上游分钟/实时权限不阻止历史 K 线。指数缓存不产生交易动作。Tushare 日线按官方手/千元口径转换；AKShare 指数未核定量能单位时留空，不猜单位。

## 本机归档与云端

优先让服务器保留网页所需热数据；本地电脑保存历史归档与研究产物。先量测数据库、索引、日志和备份占用，不预设服务器放不下。读取页面不反向连接用户电脑，电脑离线也可展示服务器的最后成功历史。

本版新增只读导出：

```bash
python scripts/archive_market_history.py --output <仓库外的新私有目录> --codes 510300.SH 512480.SH --limit 1500
```

导出 gzip JSONL、代码/日期/复权/来源及 SHA256 manifest；不包含持仓或凭据，不调用 Provider/AI，不修改数据库。最多100个显式代码，每标的最多5000条；同目录拒绝覆盖。无 manifest 的目录是不完整产物。归档数据没有因此取得导入资格。

**尚未实现：本地行情包自动签名上传、可信重导入和冷数据自动淘汰。** 已有研究 Bridge 传的是研究结果，不是通用行情同步。不得把归档工具描述成自动双向同步；不得用网盘同步正在运行的 SQLite，不向外网暴露 PostgreSQL。

## 资格不变

历史可看、量价可算、预测校准、可操作是不同门禁。正式期限仍1/3/5/10日；一个月只登记后续研究需求。因子勾选是诊断实验，不直接输出有效概率或更新策略权重。真实分钟 PIT、交易约束、样本外与 Shadow Run 不因本版本升级而通过。
