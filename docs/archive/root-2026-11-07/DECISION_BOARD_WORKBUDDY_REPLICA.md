# WorkBuddy 风格 ETF 决策评分台（历史视觉实验记录）

> 状态：**历史设计依据，不是当前计算/路由合同。**  
> 当前 UI 规则请读 `UI_UX_CONTRACT.md`；当前项目总交接请读 `PROJECT_HANDOFF_20260906.md`。

## 1. 当时为什么做这个实验

用户希望首页从“工程控制台”变成一个更适合每日决策的金融看板：

- 评分/强弱一眼可见；
- 五档动作分组清楚；
- 每个指标旁边直接解释，不要求用户记公式；
- KDJ J=90/100、RSI、MACD、量能、forecast confidence 有明确阈值语义；
- 数据来源、时效、Mock/退化不能藏在后台；
- 点击 ETF 可以继续深研判。

因此创建了 `decision_board_workbuddy.html/css/js` 的视觉/信息架构实验。

## 2. WorkBuddy 到底被“复刻”了什么

复刻的是**核心信息架构**：

- 宽表 + 分组；
- 强弱颜色；
- 指标解释；
- 预测周期；
- 置信度；
- 数据来源/时效；
- 单标的详情入口。

不是：

- 像素级 CSS；
- 未确认许可证的外部源码；
- WorkBuddy 的完整运行逻辑；
- 外站特有组件库。

历史自动环境无法读取 WorkBuddy 动态分享页，因此项目从未具备“严格一比一复制”的证据。实现依据用户描述、当时已有截图/上下文和本项目数据合同。

## 3. 当时的前端评分实验

早期 WorkBuddy 页为了强化视觉解释，曾有一套读取层综合分：

| 维度 | 早期实验权重 |
|---|---:|
| 趋势（MA + MACD） | 22% |
| 动量（KDJ + RSI + TD9） | 22% |
| 量能 | 14% |
| 结构/支撑压力 | 14% |
| 当前 forecast | 20% |
| 数据资格 | 8% |

这套分数当时明确“不覆盖生产分级”。

### 现在的裁决

v0.8 架构收敛后，**前端不得再维护会影响当前判断的第二套计算权威**。当前动作、指标状态、forecast、S/R 都应读后端/持久化权威结果。

因此上述权重只保留为历史 UX 实验记录，后续 Agent 不得把 `scoreRow/maScore/...` 恢复成 current action 的依据。

## 4. 颜色实验对当前仍有价值的部分

当时形成的“强弱有清楚色阶”仍被保留为 UX 思想，但具体色值不构成固定合同。

当前优先遵守：

1. 中国行情习惯：上涨/强势为红/暖色，下跌/风险为绿；
2. 五档动作有稳定、可辨别的语义层级；
3. forecast scenario 使用独立紫/虚线/半透明；
4. unavailable/degraded/mock 使用明确警告，不靠颜色暗示；
5. 详见 `UI_UX_CONTRACT.md`。

## 5. KDJ J 值解释（仍可作为当前展示语义参考）

- `J > 100`：超买/钝化，短线回撤风险高；
- `90 <= J <= 100`：偏热，不追高；
- `70 <= J < 90`：偏强但仍有余量；
- `30 <= J < 70`：健康区；
- `10 <= J < 30`：低位，等待拐头；
- `J < 10`：极低/超卖，但不等于立即买入；
- KDJ 死叉优先表达风险。

这些是展示解释，不是单指标自动交易规则。

## 6. 这个实验后来演化成什么

WorkBuddy 实验里真正有价值的部分已经进入正式产品演进：

- 首页五档决策总览；
- 统一动作语义；
- 明确数据资格；
- 1/3/5/10 forecast；
- 全局 `/etf/{code}` 详情；
- Zone 支撑/压力；
- 板块/持仓/研究任务式导航。

而“多页面各自维护详情/评分”的部分已经被后续收敛淘汰。

## 7. 后续 UI Agent 应该怎么用本文

可以参考：

- 信息密度；
- 表格分组；
- 指标解释靠近数值；
- 颜色需要明显语义；
- 数据来源/置信度必须可见。

不能参考为：

- 当前路由；
- 当前 score 算法；
- current action 来源；
- forecast horizon；
- 当前页面技术实现。

这些一律以 `docs/README.md` 所列当前权威文档和 main 测试为准。
