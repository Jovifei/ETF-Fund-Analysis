# UI / UX 当前合同：页面、组件、颜色与视觉参考

更新时间：2026-09-06
适用范围：所有用户可见 Web 页面

本文回答一个最容易被后续 Agent 误解的问题：**页面到底要“像谁”，颜色和组件应该遵守什么，哪些只能借鉴不能照抄。**

---

## 1. 总原则

UI 的目标不是复制某个站点，而是让用户在 14:30 前后快速完成：

> 找板块 → 选 ETF → 看持仓/自选 → 点进统一详情 → 看证据 → 做五档研究判断。

因此 UI 优先级从高到低是：

1. 当前动作和数据资格是否清楚；
2. 强弱/风险是否一眼可见；
3. 预测、指标、支撑压力的解释是否紧贴数值；
4. 页面切换是否符合用户任务；
5. 最后才是装饰、动画和像素级相似度。

## 2. 当前稳定路由

| 任务 | 路由 | 导航层级 |
|---|---|---|
| 决策 | `/` | 一级 |
| 板块 | `/boards` | 一级 |
| 持仓 | `/holdings` | 一级 |
| 研究 | `/research` | 一级 |
| 新闻 | `/research/news` | 研究子页 |
| 系统 | `/system` | 管理/工具入口 |
| 14:30 | `/decision/1430` | 决策二级模式 |
| ETF 详情 | `/etf/{ts_code}` | 全局对象详情 |

旧 `/legacy`、`/workbench/1430`、`/workbench/kline` 只用于兼容，不应出现在新导航中。

### 页面切换的唯一心智模型

- 点“决策”永远回 `/`；
- 点“板块”永远去 `/boards`；
- 点“持仓”永远去 `/holdings`；
- 点“研究”永远去 `/research`；
- 点任意 ETF 代码/名称/列表条目，若语义是“看这只 ETF”，统一去 `/etf/{code}`；
- 14:30 不是一级 tab，而是决策的模式入口；
- 不再从一个 ETF 列表打开“这个页面自己维护的另一套详情抽屉”。

## 3. 视觉参考来源

### 3.1 WorkBuddy：最重要的信息层级参考

WorkBuddy 风格实验被用于回答：

- 哪些读数应最突出；
- 如何把五档动作分组；
- 如何让指标解释不依赖用户记公式；
- 如何把 `J=90/100`、RSI、MACD、量能、forecast confidence 放在一屏内；
- 如何让数据源/时效/风险不是页脚小字。

**边界**：历史自动环境无法直接读取 WorkBuddy 动态分享页，所以项目从未建立“像素级复制”合同。任何后续 Agent 都不得声称 UI 必须精确复刻 WorkBuddy 的 CSS、字体、尺寸或颜色值。

### 3.2 illusionno/fund-analysis-matrix：暗色金融卡片/表格参考

借鉴的是：

- 暗色背景；
- 高密度金融表格；
- 标的卡片；
- 自选 hydrate 后刷新；
- 点击标的看详情；
- BFF 隔离浏览器和数据源。

没有复制 React/Vite 技术栈；当前项目仍偏向原生 JS/CSS，降低个人 ECS 部署复杂度。

### 3.3 中国证券行情习惯：颜色语义参考

必须优先遵守中国用户习惯，而不是欧美交易终端默认：

- **上涨/偏强：红色或暖色系**；
- **下跌：绿色**；
- 风险/阻断是“状态语义”，可使用绿、琥珀、红色警告或去饱和样式，但必须避免与“上涨红”混为同一含义；
- 中性/不可用：灰/蓝灰；
- 警告但不代表涨跌：琥珀/橙；
- forecast 情景/未来非实际数据：紫色/独立虚线语义。

不要因为使用某个海外图表库就自动把“涨绿跌红”切成欧美习惯。

### 3.4 KLineChart / ECharts / TradingView Lightweight Charts

这些只属于“图表能力参考”。Master Plan 曾提出 Lightweight Charts，但当前运行实现是 CSP-safe 自绘 Canvas。

现有 Canvas 已有：

- 滚轮缩放；
- 拖拽平移；
- 双击复位；
- 十字光标；
- OHLC tooltip；
- 支撑/压力 Zone；
- 预测情景蜡烛。

除非存在明确性能、维护或可访问性问题，否则不要为了“跟计划一致”而重写图表引擎。

## 4. 颜色语义合同

### 4.1 行情涨跌
- 正收益 / 上涨：红/暖红；
- 负收益 / 下跌：绿；
- 0 / 缺失：中性灰。

### 4.2 五档 current action
具体色值允许页面主题微调，但语义顺序必须稳定：

| 动作 | 视觉语义 | 推荐色域 |
|---|---|---|
| 可加仓 | 最积极、但仍为研究态 | 红/暖红 |
| 可入场 | 积极 | 红橙/亮暖色 |
| 可试探 | 有机会但证据弱 | 金/黄 |
| 观望 | 中性/等待 | 蓝/灰蓝 |
| 减仓 | 风险/降低暴露 | 绿或独立风险强调色，必须与上涨红的“行情方向”语义区分 |
| 数据异常 | 不可用于动作 | 灰/去饱和 |

**禁止**：只看颜色就让用户误以为“可加仓=系统下单”。文案必须继续标注研究属性。

### 4.3 数据资格

- verified/fresh：正常状态；
- provisional：明确“临时观测”；
- stale/degraded/unverified/missing/mock：警告/降权；
- blocked：必须显示“不可操作/数据资格不足”，不能仅用低对比度小字。

### 4.4 Forecast

- 历史实际 K 线与未来情景必须视觉分区；
- forecast 建议使用紫/虚线/半透明带；
- 必须出现“非实际结果/研究情景”；
- 未校准 `p_up` 不得标“上涨概率”。

## 5. 组件合同

### 5.1 顶部导航

一级入口只承担任务切换：决策 / 板块 / 持仓 / 研究。

- 14:30 放在决策的二级入口；
- 系统管理不应和高频业务任务抢同等视觉权重；
- 当前页有 `aria-current`/active 状态；
- 登录、刷新、连接状态属于右侧操作区，不和业务导航混在一起。

### 5.2 决策总览

必须优先展示：

1. 快照时间和数据状态；
2. 五档数量；
3. 标的身份；
4. 今日/较昨日/近周；
5. MA/MACD/KDJ/RSI/TD9/量能等解释；
6. 当前 1/3/5/10 预测；
7. canonical grade/action；
8. 理由/风险/数据资格。

页面不允许重新计算另一套 current action。

### 5.3 板块页

板块页服务“找机会”，不是把板块做成第二个 ETF 详情页。

- 清楚区分：板块自身 breadth/snapshot vs ETF 代理；
- 没有真实板块 breadth 时显示不可用；
- ETF 代理只能说明“该主题对应的可交易代理”，不能冒充板块指数；
- 成员/主 ETF 点击直接进入 `/etf/{code}`。

### 5.4 持仓页

必须突出“和我有关”：

- ETF 身份；
- 份额/成本；
- 现价/市值/盈亏；
- 当前 canonical action；
- 1/3/5/10 预测；
- 最近支撑/压力；
- 自选管理；
- 修改/删除持仓。

后续独立页面拆分时，优先把成本线/风险预警和详情页打通，不要先加装饰。

### 5.5 研究中心

研究中心不是另一个“决策首页”。

适合放：

- Signal Center 深层归因；
- 新闻证据；
- 市场环境；
- 研报/审计/研究工具。

不适合：再次复制五档主决策表并产生另一套入口。

### 5.6 ETF 详情

`/etf/{code}` 是全局唯一单标的深研判载体，应逐步收敛以下组件：

1. 头部身份/现价/当前动作/持仓信息；
2. 1/3/5/10 预测卡；
3. 日K/30m/60m 切换（无真实分钟数据则禁用）；
4. 交互 K 线；
5. 支撑/压力 Zone；
6. MA/MACD/KDJ/RSI/TD9/缠论近似/成交密集过滤；
7. 新闻/风险证据；
8. 成本线（有持仓时）。

### 5.7 错误态/空态

错误态是产品的一部分：

- API 失败：明确“数据暂不可用”；
- 未同步分钟线：按钮 disabled + 原因；
- 无 forecast：显示 unavailable，不填 0；
- provider degraded：显示来源和原因；
- Mock：明显标记 DEMO/Mock；
- 不允许读取旧静态 snapshot 假装页面“正常”。

## 6. KDJ / RSI / Confidence 的文案合同

### KDJ J
当前 `config/strategy.json` / WorkBuddy 展示语义使用 20 / 90 / 100 三个关键边界：

- `J > 100`：超买/钝化，短线回撤风险高；
- `90 <= J <= 100`：偏热，谨慎追高；
- `20 <= J < 90`：正常/健康区；若 K≥D 则趋势结构更健康；
- `J < 20`：低位/超卖，等待拐点确认，不等于自动买入；
- KDJ 死叉优先表现风险，即使 J 值不高也不能只按区间写“健康”。

历史 WorkBuddy 实验曾讨论更细的 10/30/70 分段，那些仅保留在历史设计文档，不是当前策略/展示合同。若以后要改边界，必须同时更新配置、展示语义和测试。

### RSI
当前显示语义遵循 70/50/30 分带；不要重新创造不同边界，除非策略/展示合同明确升级。

### Forecast confidence
- `conf >= 60`：可参考；
- `40 <= conf < 60`：弱信号；
- `conf < 40`：忽略/基本不参与判断。

这些是展示/证据强度语义，不等价于真实上涨概率。

## 7. Responsive / 浏览器验收

至少检查：

- 1440px 桌面；
- 1024px 笔记本/平板横屏；
- 390px 移动端。

必须验证：

- 顶栏导航不把刷新/状态挤到不可用；
- 宽表可横向滚动且首列身份可辨识；
- 点击行和内部按钮不互相抢事件；
- 详情页图表在窄屏不溢出；
- forecast 非实际边界仍可读；
- active nav 与实际 URL 一致；
- 旧 URL 兼容跳转后用户不会落错模块。

## 8. 明确禁止

后续 UI Agent 不得：

- 为了“更像某网站”复制未经确认许可证的源码/资源；
- 恢复前端二次打分；
- 在不同页面给同一 ETF 不同 current action；
- 把 ETF 代理涨跌写成板块指数涨跌；
- 把 `not_calibrated` 写成真实上涨概率；
- 用日 K 补成分钟 K；
- 用 Mock/静态 snapshot 遮住 API 错误；
- 把 14:30 重新提升为和决策/板块/持仓/研究并列的一级产品；
- 为了技术洁癖强制替换已经满足用户体验的 Canvas 图表。

---

## 9. 未来 UI 重构的正确顺序

1. 先拆掉 legacy 大壳：独立 Holdings / Research / System；
2. 让 Decision 与 14:30 共用同一组件/状态；
3. 把持仓成本线、个人风险提醒真正接到 `/etf/{code}`；
4. 再优化 responsive、表格密度和图表交互；
5. 最后才评估是否替换图表库。

任何 UI 重构都必须保持现有 API/数据真实性/canonical action 合同不变，除非另开后端契约 PR。
