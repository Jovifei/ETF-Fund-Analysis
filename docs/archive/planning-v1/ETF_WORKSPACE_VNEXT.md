# ETF 低频研究工作站：vNext 总方案与执行账本

版本：planning-v1，2026-09-06。状态：**研究与规划；尚未开始业务实施**。
代码基线：`3c7bdc7ff36b3dea482651e087127a33c4974903`；应用仍为 0.8.0。

## 1. 本轮范围与目标修订

用户最新要求：先深入学习指定项目、补充开源检索、形成长期可执行方案并更新 docs；本轮不部署、不安装第三方 Skill、不重构代码、不启用定时或交易。本文件记录需求，不构成生产执行授权。

最终产品是**个人主观决策、低频执行的 ETF 研究工作站**：全市场发现 → 搜索 ETF → 数据看板/自选 → 个人持仓 → 技术与新闻证据 → 可选 AI 研判 → 14:30 人工判断 → 事后复盘。第一阶段 ETF，第二阶段个股。服务器负责轻量持续数据与展示，本地电脑承担有界研究任务。不是自动交易机器人，也不是把几个完整交易系统装在一台小服务器上。

最新截图明确指定 KairoTrend 式左侧栏和顶部搜索。旧文档的“固定四个顶部入口”“UI 必须排在所有验证之后”“不再加页面”不再约束目标。**代码证明当前做到了什么，不能证明用户放弃了尚未实现的需求。** 安全、数据真实性、版本与审批边界继续遵守 `AGENTS.md`。

## 3. 每一步如何做

### M0：研究和规划（本轮）

交付：开源吸收矩阵、UI/搜索合同、本地研究桥接合同、因子/Skill治理、执行账本、过程记录。只完成定向文档/源码审阅，不声称全仓审计、上游安装成功或视频已看完。未读到的动态演示列入待补证，不阻塞已明确的布局需求。

### M1：先冻结一套可评审页面原型

输入：`UI_UX_CONTRACT.md`。未来实现仅改共享壳、路由映射、组件和显式演示夹具，不改指标/策略。保留现有稳定 URL；新增分析/因子/个人中心路由在路由合同 PR 中批准。

输出：桌面/窄屏的总览、数据看板、AI空态、持仓、搜索多动作原型；标注 DEMO，绝不接静态假数据作为生产 fallback。验收：键盘导航、行内按钮不冒泡误跳、浏览器返回保留筛选/标的，AI未配置也可用。回滚：只撤新壳，不改数据库。

### M2：最小可用 ETF 纵向闭环

优先复用现有后端：搜索合法 ETF → 加自选 → 开单 ETF 图 → 录入/导入持仓 → 看成本/盈亏/同源 S/R → 回总览。全市场证券目录与需要持续计算的研究池分离；尚未初始化的标的显示进度/原因，不伪造行情。

拆为小 PR：共享导航与搜索；单 ETF 组件；持仓导入/成本线；总览覆盖率。先验证日K；30m/60m 数据未取得资格时明确禁用。文件/OCR 确认前零持仓写入，重复确认幂等，多用户跨读/跨写拒绝。

### M3：本地 Vibe 只读试点（未来获得执行授权后）

第一优先候选 Vibe-Research，独立目录/进程/依赖/产品 CODEX_HOME，不覆盖本项目，也不自动改用户全局 Codex 配置。先做环境/许可证/安装脚本与网络出口审查；模型登录由用户在官方流程完成。实测 Node/Python/Codex 版本、RAM峰值、耗时、调用费用和重试，不以 README 性能作承诺。

先选一份市场复盘或新闻证据任务，再选一个 ETF 技术解释任务。Vibe 的原生六阶段公司研究不直接套到 ETF：ETF 用我们的指标快照与持仓/行业映射构造证据，个股财务深研留给第二阶段。输出合格研究包，暂不自动上传。失败时移除隔离试点即可，主站不受影响。

### M4：本地研究结果进入网页

依赖 M2/M3。先实现**手动导入同一研究包格式**，再接本地主动推送；不要先做远程遥控电脑。复用 ReviewService 的候选/hash/人工接受思想，但新增来源不能伪装成既有 allowlisted runner，必须单独扩展接口、权限与测试。

输出：网站能显示任务进度、来源、时间、正文、引用、冲突、失败原因及个人/共享权限。研究包校验、重复、过期、跨用户、签名/hash不匹配、恶意 Markdown 和未来时间必须有失败测试。停止 connector 或撤销发布即可回滚；不修改行情/动作表。

### M5：低频任务运营

手动往返稳定后，再授权日程。先单一任务执行器、并发1；收盘后一次公共复盘，用户主动点选少量 ETF 深研。新闻按去重事件批量解释，产业催化默认每日批次，因子大检验每周/按需；不复制 tick 高频全市场扫描。

交易日/节假日依赖现有日历；14:30 先形成确定性快照，AI迟到不能冒充14:30已知信息。设置每日金额/调用次数/最大时长/产物大小预算；预算初值经 M3 实测后确认，不承诺免费无限调用。电脑离线时主站正常展示最后成功研究的日期，不显示“实时连接”。

### M6：因子、风格与严肃验证

目录可容纳120+候选，但首批建议只选8–12个可解释、数据够用的因子/因子族，小规模逐项验证。实现注册表、相关性热力图、IC/OOS、版本/启停；个人持仓风险和市场预测分离。先纳入趋势/防守等方法论模板，再评估具体交易风格，不复制短线打板策略。

并行完成真实 14:30 point-in-time、费用/滑点/可成交性、事件回测、1/3/5/10期限校准与影子运行。至少20个交易日观察是工程观察起点，**不是统计有效性的充分证明**。校准通过和策略有效是两种验收，均需明确样本/阈值/批准。

### 第二阶段 P2：个股扩展（独立批准）

扩展证券类型/交易约束、历史成分与财务披露 PIT；再接 Vibe 公司六阶段、TradingAgents基本面、多来源公告/研报、机构持仓/龙虎榜风格假设。先证明数据权利、披露可见时间、退市/停牌样本处理与回测口径，再上线个股结论。沿用同一壳与身份解析，不重建第二个网站。

## 4. 主依赖与可并行关系

```text
M0 规划 → M1 原型 → M2 无AI的ETF闭环 ───→ M4 研究包进入网站 → M5 低频运营
                  M3 本地Vibe隔离试点 ──┘
数据真实性 / 14:30 PIT / 校准 / M6因子治理 ───────────── 并行研究门禁
第二阶段个股：第一阶段稳定后另行启动
```

页面可用不等于预测可信；预测未校准不意味着不能先交付诚实标注的页面。20D、图表库替换属于保留待评审项，不能因未实现就写成“用户已取消”，也不能在本轮擅自启用。

## 5. 每个实施 PR 的证据

开始：需求ID、基线SHA、复现/失败测试、数据/策略版本、依赖和边界。结束：改动文件、测试命令/退出码/时间、截图（脱敏）、CI链接、未完成项、回滚路径。策略/指标/预测改动另增版本、泄漏检查、样本外报告和人工批准。

本轮只验证文档结构、相对链接、受限范围、认证关键字和敏感信息；没有替新代码做浏览器验收，也没有实测外部工程。下一位 AI 默认先继续需求评审；只有用户授权进入实施时才从 M1 开始。
