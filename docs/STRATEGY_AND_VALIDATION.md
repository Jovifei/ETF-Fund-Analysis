# 策略与验证口径

- 均线：5/10/20/30/60；
- MACD：12/26/9；
- KDJ：9/3/3，K/D 初始值 50；
- RSI：6/12/14；
- ATR：14；
- BOLL：20，2 倍标准差；
- TD Setup：自定义 9 计数，仅表示本项目口径，不宣称等同商业终端完整 TD Sequential。

公式变更必须升级 `indicator_version`，并用固定样本重新测试。

## 当前评分

候选分综合：

- 技术趋势 35%；
- 反向风险分 20%；
- 新闻主题 20%；
- 1/5/20 日预测 15%；
- 组合适配 5%；
- 基金交易质量 5%。

这是工程初始值，不是已证明的最优参数。真实数据回测前不得为了某一天表现随意调整。

## 基金交易质量

当前可用字段：

- 盘中成交额；
- 溢价/折价；
- 20 日波动；
- 60 日回撤。

待补齐字段：

- 基金规模；
- 日均成交额和价差；
- 管理费/托管费；
- 跟踪误差；
- 申赎/限购状态；
- 主题持仓纯度。

## 市场状态门控

以 `510300.SH` 为默认代理，根据其：

- 风险分；
- 20 日年化波动；
- 60 日回撤；

划分 `low_risk / normal / high_risk / extreme_risk`，对应组合暴露上限 100% / 70% / 40% / 10%。这属于风险控制，不是对大盘涨跌的确定性预测。

## 迟滞

借鉴 ETF 轮动项目中减少无效换手的思想，本项目设置：

- 状态最短保持 30 分钟；
- 新旧分数变化不足 5 分时，优先保留原状态；
- 单次目标权重变化不超过 10%；
- 单基金目标上限 25%；
- 单主题目标上限 40%。

这些参数必须通过事件驱动回测后再封版。

## 相似样本预测

每个历史时点生成由趋势、动量、波动、回撤、量能等构成的状态向量。当前时点仅与更早的候选样本比较，选取相近样本后统计未来收益分布。

输出：

- `p_up`；
- `expected_return`；
- `q10/q50/q90`；
- `sample_count`；
- `similarity_distance`；
- `confidence`；
- `calibration_status`。

未校准置信度封顶 55。

## Walk-forward 验证

`ForecastValidationService` 沿时间前进，在多个历史观察点重新做相似预测，统计：

- 方向准确率；
- Brier score；
- 期望收益 MAE；
- 80% 区间覆盖率；
- 概率校准分桶。

验证结果写 JSON 报告，但不会自动把模型状态改为 calibrated。人工封版至少还需要：

1. 标的覆盖和样本量满足要求；
2. 1/5/20 日分别评估；
3. 多个市场状态下表现不过度失衡；
4. 与简单基准相比有稳定增益；
5. 事件驱动组合回测通过；
6. 记录数据区间、代码 commit、参数 hash 和批准人。

## 事件驱动轮动回测（已实现研究基线）

`RotationBacktestService` 借鉴社区中“研究层与生产审计层分离”的方法，当前固定口径为：

- 第 `t` 日收盘后只使用截至该日的日线形成决策；
- 第 `t+1` 日开盘执行，报告同时保存 `feature_date_max`、决策日和执行日；
- 5/20/60 日动量、20 日趋势和低波动横截面排名；
- 绝对动量为负时允许转现金，而不是永远选择“跌得最少”的标的；
- 默认最多 4 只、每个一级主题最多 1 只、单基金上限 25%；
- 最短持有 9 个交易日和 0.10 横截面排名迟滞；
- 以 510300 的均线和波动率分位决定 100% / 70% / 40% / 10% 总暴露；
- 100 份整手、手续费、最低佣金和双向滑点；
- 无开盘价时不交易，持仓按最近可得收盘价估值；
- 输出权益曲线、成交、决策、回撤、Sharpe、Calmar、换手和基准超额。

运行：

```bash
fund-decision run-task backtest_rotation
```

配置在 `config/strategy.json -> backtest`。该报告明确标记 `unsealed_research_baseline`；运行任务不会自动改写实时策略阈值。

## 仍需补足的生产审计

当前基础引擎还不能替代真实市场审计，部署后必须继续补充：

- 交易所停牌、涨跌停和无成交导致的无法执行；
- 不同 ETF/LOF 的实际最小交易单位；
- LOF 折溢价、申赎和限购状态；
- 现金收益或货币基金替代；
- 复权、拆分和异常大涨跌的人工核验；
- 一套独立实现的向量化或 AKQuant/Backtrader 引擎对账；
- Train → Rolling → Holdout → Event-driven 四层验证；
- 多组费率、滑点和执行时点敏感性分析。

只有当第二引擎与当前事件驱动结果的差异逐项可解释，并通过真实样本外验证，才可建立 sealed strategy 记录。
