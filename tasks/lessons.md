# 工程经验

- 用户的目标包含每日拉数、决策、AI解释、网站更新和邮件时，要按同一交易日/槽位逐段验收并标明运行归属；一次 accepted、版本发布或 Windows 最后退出 0 不能代替全天自然任务成功。仓外邮件需核真实发送头与投递记录，不能凭仓库无 SMTP 推断从未发过，也不能把数据资格未知扩大成研究展示与故障通知全部停机。


- 解释本地优先系统的存储位置时，不能只凭设计文档或 SQLite 文件大小说“数据都在本机”。要同时核本机与云端表行数/时点、展示包和遗留库，并分别报告磁盘、备份、镜像与 RAM；旧云端数据保留不等于新采集仍写云端。用户纠正时先复核再下结论，不清理受保护资产。

- 用户因可见终端要求删除频繁任务后又明确希望保留执行时，应先保存原任务 XML、说明停更影响，再用无控制台启动方式恢复原触发器并验证退出码与窗口；不能把隐藏任务列表的设置误当成隐藏进程窗口，也不能让静默运行吞掉错误记录。

- 用户指出线上空白和旧报价时，先实测默认 Reader、代码身份与每个页面的报价来源。已接收展示包到期后仍可读取并标记历史；新包激活才受有效期限制。不能把“包过期”单独当作空白根因，也不要通过重复封装旧数据制造新鲜感。local_bundle 模式的自选、搜索和持仓应使用同一批准展示包；覆盖外标的明确缺价。
- 用户明确将收藏作为当前所持基金的代码清单时，不再催要 CSV，也不能把收藏自动变成带份额和成本的持仓记录。保留真实空态，说明金额与盈亏仍不可计算。

- 跨 Agent 交接出现晚于本地验收的新网页复审缺陷时，不能沿用上一 PR 的“已完成”结论。先读完整接手文档，核当前 PR/分支祖先和精确测试收据；把新增缺陷当同一授权阶段的未完工作，先 RED 后最小修复，并为新 SHA 重新跑完整测试、CI 与网页复审。旧候选 PASS 只作为基线，不能替代最终合并门槛。

- 远端 ChatGPT 的一次交接须是完整的大阶段合同：先审核当前 GitHub 基线与已完成工作，修复审查发现的问题，再依据总目标和现阶段证据选择并执行下一阶段，完成测试、独立复审、GitHub 提交及固定 SHA 交接。不能把一个几十秒即可完成的盘点或单点建议拆成一次远端任务；本地只在收到固定提交后独立接收验证。代码写入范围须先向 Jovi 征询授权。

- 调度验收必须用真实TaskService返回结构经过compute hook、持久台账和验收器闭环；不要在夹具中凭空添加coverage/scope字段。控制覆盖证明可另建，但原始TaskRun和行情partial/质量不得改写。时效按实测分项定位，跳过必然无合格结果的请求须保持旧选择优先级并记录真实审计，不能降低目标。

- 用户重新要求网页GPT协作时，以最新要求恢复规划与复审；上一轮临时免除不能自动延续。先核连接与实际读取成功，再提交固定候选和测试证据，不把连接正常或计划通过称作代码复审通过。
- 迁移定时任务先读取真实Trigger StartBoundary及Settings；NextRunTime不是原触发边界，不能据其秒数编造精确迁移守卫。保护性预览失败后保留证据，修正并重新冻结/验证。

- 图形、图例和依据必须共享同一方向枚举合同；兼容字段只在主字段缺失时使用，未知保持中性，不能用子串或默认分支推断金融方向。
- 价格口径门禁覆盖所有消费研究价格的几何通道，包括斜向趋势线；阻断错配原始投影的同时，必须保留合法研究线、同口径原始线和独立成本/量额数据。
- 用真实投影与适配器、不同原始/研究价格的夹具检查绘图调用，并配对正反断言；相等价格或过度mock会掩盖错配。
- 当前时间、版本、输入内容与快照身份应有独立证据；未知量额、时间、PIT或许可不能由非空响应、页面可用或测试通过升级。
- 本地验证、精确提交CI、部署、正常私有线上验收及实体手机是不同门槛；历史发布计数不能继承为新版本或全项目完成率。
- 发布前检查完整载荷而不只看新增diff。状态文档仅保留当前目标、必要版本/证据和未完成门槛，移除个人路径、生产统计与内部操作历史；不把不必要内容搬到另一发布文件。
- 文档精简时保留实现/测试哈希、阶段ID与验收状态，使用台账生成可读视图；字节未变时复用已绑定验证，不重复全量测试来制造新结果。
- 遇阻先区分授权、载荷范围和执行访问问题，保存具体动作与证据；继续不依赖阻塞的核对，调整范围须经过明确确认，换工具或编码不能解决底层范围问题。
- 冻结源码不冻结上游安全公告。长流程发布前先做轻量依赖门禁，比较官方最小修复版本和必要闭包；不要盲目audit-fix升级所有包或放宽阈值。
- 测试框架主版本更新须验证完整前端、mock隔离、类型与构建；无变化的后端证据按哈希复用。浏览器启动失败须与页面断言失败分开，不能计为产品通过。
- 文档脱敏也会改变跨文件契约。精简前搜索代码和测试对文档的读取，保留可机器验证的必要部署要求；相关测试必须重跑，不能只凭后端源码字节未变复用旧结果。移除个人路径与生产统计不应删除浏览器数据库认证、迁移和安全Cookie的说明。
- 授权长阶段不能把读取困难或中间汇报当成停止指令；用户明确改为本地执行、网页复审后，保持单一源码写入者，完成固定提交、真实验证和集中回传，资源资格阻塞仅停相关步骤。
- 本地一次性任务、实际回环TLS、应用Cookie路径、公网生产和长期运行要分别绑定源码与证据；不把Mock或单次成功提升为真实数据或上线验收。

- 用户要求“整理修复任务并执行”时，计划只是验收合同；必须继续到实际修复、精确测试、独立复审及已授权发布门槛，不能以计划文件或源码文件存在代替交付。

- 用户不理解准入/证据术语时，由Agent核已有来源和记录，解释具体影响与选择；不把结构化技术材料整理转给Owner。区分研究展示、来源资格、操作级信号；不要擅自放大为全系统停机门槛，也不伪造已验证。

- 发布前核实际宿主Python、SSH身份与既有服务健康契约；禁用健康检查的scheduler需按稳定运行验收，不能用全局Compose wait误判。私有700目录在应用UID只读容器验证，不放宽ACL。
- 有依赖的工具调用先检查上一调用的exit_code/session_id；未结束或失败不得推进后续变更。配置差分先列计划内角色变更，避免把预期展示模式当漂移并误停任务。
- 安全检查先核遍历边界，在干净Git index/checkout执行原扫描器；不要把Owner忽略的历史工作树、私有配置和生成文件纳入发布源码扫描。

- 测试库是 SQLite，`DateTime(timezone=True)` 只保留墙钟、丢弃偏移量：同刻的 UTC 行比 Asia/Shanghai 行少 8 小时，`ORDER BY started_at DESC` 会把 UTC 行排到后面。样本行必须用应用时钟（`settings.timezone`）打时间戳，否则只要同会话里产品写入的行凑满 bootstrap 的 20 条窗口，新增任何一条 TaskRun 就会把断言挤出窗口。排查红测先跑基线分支全量，区分“既有失败”和“被自己新增状态顶破的临界假设”。
